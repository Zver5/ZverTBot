# Changelog

Все заметные изменения ZverTBot.

## [1.4.1] - 2026-09-26

### Fixed

#### Telegram / Markdown

- Исправлено отображение имён клиентов с символом `_` в Telegram Markdown.
- Имена клиентов внутри code span теперь передаются без лишнего экранирования.
- Имена клиентов в Markdown-выделении корректно экранируются.
- Исправлено отображение имён клиентов в сообщениях QR-кодов и конфигураций.
- Добавлены регрессионные тесты для имён клиентов с `_`.

## [1.4.0] - 2026-09-16

### Added

#### VPS Monitoring

- Добавлена persistent очередь Telegram-уведомлений о переходах состояния.
- Добавлена повторная доставка неотправленных Telegram-уведомлений.
- Добавлена изоляция ошибок доставки между несколькими административными чатами.
- Добавлены тесты очереди уведомлений, retry и порядка сохранения состояния.

#### VPS Status / Statistics

- Добавлены дополнительные поля состояния клиентов AmneziaWG для VPS Status.
- Централизована подготовка canonical VPS Status payload.

### Changed

#### VPS Monitoring

- Уведомление теперь сначала сохраняется в persistent очередь, затем сохраняется состояние мониторинга и только после этого выполняется доставка.
- При сбое Telegram состояние мониторинга не теряется, а уведомление остаётся в очереди до следующей успешной доставки.
- Повторная отправка одного и того же перехода в одном чате подавляется очередью.
- Для AWG используется фактически обнаруженный экземпляр `awg-quick@*.service`, без предположения о конкретном имени интерфейса.

#### Deployment / Installer

- Усилена проверка состояния пакетного менеджера после установки системных пакетов.
- Улучшена диагностика незавершённого состояния `dpkg`.

### Fixed

#### VPS Monitoring

- Исправлено обнаружение `awg-quick@awg0`: ранее имя unit обрезалось некорректно.
- Исправлена ситуация, при которой ошибка отправки Telegram могла привести к потере уведомления о переходе состояния.
- Исправлена доставка уведомлений при нескольких административных чатах: сбой одного чата больше не блокирует остальные.
- Исправлено обнаружение фактически активного экземпляра AmneziaWG вместо использования только template unit.

#### Architecture / Runtime

- Добавлена защита от запуска нескольких экземпляров VPS Monitor через `flock`.
- Централизована работа с состоянием системных сервисов.
- Удалено дублирование логики проверки состояния сервисов и валидации.
- Централизована работа с runtime-состоянием AmneziaWG.

#### Telegram / Statistics

- Локализованы отображаемые названия callback-команд в системной статистике без изменения внутренних callback ID.
- Для динамических callback-сценариев добавлены человекочитаемые русские названия.

### Tests

- Добавлены проверки persistent очереди Telegram-уведомлений.
- Добавлены проверки повторной доставки после ошибки Telegram.
- Добавлена проверка независимости уведомления о восстановлении от неотправленного уведомления о падении.
- Добавлена проверка порядка `queue → save state → delivery`.
- Расширены тесты обнаружения AmneziaWG.
- Полный набор тестов после изменений проходит успешно. **1511 passed**.

## [1.3.0] - 2026-09-13

### Added

#### Home Assistant / VPS Status

* Добавлена модель канонического статуса VPS.
* Добавлен отдельный источник данных VPS Status с canonical endpoint `/vps-status.json`.
* Добавлен CLI для получения VPS Status по SSH.
* В VPS Status сохранены системная информация, состояние сервисов, backup, Fail2Ban, AmneziaWG/Xray, подключения и GeoIP.
* Подготовлена архитектура получения VPS Status через существующий SSH-туннель или Direct SSH.

#### Fail2Ban

* Добавлен корректный разбор истории банов Fail2Ban.
* Добавлена проверка фактического состояния IP перед выполнением `unban`.

#### AmneziaWG / Statistics

* Добавлены отдельные поля состояния клиентов AmneziaWG.
* Добавлена обработка фактических значений трафика клиентов AmneziaWG.

#### Deployment / Installer

* Добавлена проверка состояния `dpkg` и APT до и после установки системных пакетов.
* Добавлена проверка `xray-traffic.timer` в составе системных timers.

### Changed

#### Home Assistant / VPS Status

* Интеграция Home Assistant переведена на canonical VPS Status вместо legacy `/stats.json`.
* Passport переведён на проверку актуальности данных VPS Status.
* Для получения VPS Status не требуется открывать новые порты в Интернет.

#### Fail2Ban

* Улучшена обработка истории банов и текущего состояния Fail2Ban.
* Исключены ложные записи `preauth`, не являющиеся фактическими банами.
* Улучшена обработка операций `unban`.
* Улучшены сообщения и диагностика ошибок Fail2Ban.

#### AmneziaWG / Statistics

* Удалено искусственное разделение AWG-трафика на отдельные направления.
* Статистика клиентов AmneziaWG переведена на фактическое состояние и трафик клиентов.

#### Deployment / Installer

* Усилена проверка состояния пакетного менеджера перед изменением системы.
* Улучшена диагностика ошибок `apt-get update` и установки системных пакетов.
* Systemd timers теперь явно включаются и запускаются через `systemctl enable --now`.
* Добавлена проверка фактического состояния timers после запуска.
* Улучшена надёжность повторной установки поверх существующей установки.

### Removed

#### Legacy VPS Statistics

* Удалён legacy Stats HTTP endpoint `/stats.json`.
* Удалён устаревший путь получения VPS-данных через Stats HTTP.

### Fixed

#### Home Assistant / VPS Status

* Исправлена проверка актуальности VPS Status в passport.
* Исправлена проверка мониторинга после перехода на canonical VPS Status endpoint.

#### Fail2Ban

* Исправлен разбор истории банов Fail2Ban.
* Исправлена обработка ложных записей `preauth`.
* Исправлен `unban`: IP проверяется перед выполнением операции.

#### AmneziaWG / Statistics

* Исправлен расчёт общего трафика клиентов AmneziaWG.
* Исправлено отображение фактического состояния AWG-клиентов.

#### Deployment / Installer

* Исправлена обработка ошибок `apt-get update`, включая ошибки загрузки пакетов и репозиториев.
* Исправлен запуск systemd timers при установке.
* Исправлена проверка фактического состояния timers после запуска.
* Исправлена проверка `xray-traffic.timer` после установки.

### Documentation

## [1.2.0] - 2026-09-12

### Added

#### VPS Monitoring

- Добавлен независимый `zvertbot-vps-monitor.service` для мониторинга состояния VPS.
- Добавлен отдельный monitoring runner, независимый от Telegram polling процесса ZverTBot.
- Добавлено persistent-хранилище состояния мониторируемых компонентов.
- Добавлены event-driven уведомления в Telegram только при изменении состояния.
- Добавлены уведомления о восстановлении сервиса после состояния DOWN.
- Добавлены проверки состояния ZverTBot, Stats HTTP, backup, Xray, AmneziaWG, SSH и Fail2Ban.
- Добавлены отдельные причины отказа для systemd, HTTP, TCP, UDP, client-проверок и backup.

### Changed

#### VPS Monitoring

- Мониторинг VPS перенесён из legacy Kuma Healthcheck в независимый `zvertbot-vps-monitor.service`.
- Проверка backup переведена на результат последнего выполнения и актуальность сохранённого статуса вместо проверки активности oneshot-сервиса.
- Проверка AmneziaWG учитывает состояние интерфейса и доступность UDP-порта.
- Для `stats-http`, Xray и SSH добавлена проверка фактической доступности соответствующих сетевых endpoint'ов.
- Повторные уведомления при неизменном состоянии подавляются.
- Состояние мониторинга сохраняется только после успешной обработки уведомлений, чтобы ошибка отправки не приводила к потере события.

#### Deploy

- Installer обновлён для установки и запуска `zvertbot-vps-monitor.service`.
- Обновлён состав устанавливаемых systemd-компонентов в соответствии с новой схемой мониторинга.
- Удалены из deployment устаревшие компоненты legacy Kuma monitoring.

#### Backup

- Скрипт `scripts/backup-to-yandex.sh` приведён в соответствие с новой архитектурой мониторинга.
- Из состава backup удалены устаревшие `healthcheck.service` и `kuma-webhook.service`.
- В backup добавлен `zvertbot-vps-monitor.service`.
- Сохранено резервное копирование базы Uptime Kuma как общего системного компонента VPS.
- Обновлено описание состава резервной копии и retention.

#### Passport

- Удалены устаревшие проверки и зависимости от legacy Kuma monitoring из passport-проверок.
- Паспорт бота приведён в соответствие с новой схемой VPS-мониторинга.

### Removed

#### Legacy VPS Monitoring

- Удалён `healthcheck.service`.
- Удалён `kuma-webhook.service`.
- Удалена настройка `KUMA_HEALTHCHECK_URL`.
- Удалён legacy runtime для VPS Healthcheck и Kuma Webhook.

### Fixed

#### VPS Monitoring

- Исправлена обработка systemd oneshot-сервисов: `inactive (dead)` не считается ошибкой сам по себе.
- Исправлена обработка AWG-сервиса с `RemainAfterExit=yes`.
- Исправлена проверка backup без зависимости от `systemctl is-active`.
- Исправлено сохранение состояния мониторинга при ошибке отправки Telegram-уведомления.
- Исправлена обработка переходов состояний `UP → DOWN` и `DOWN → UP`.

### Documentation

- Обновлена документация deployment с учётом независимого VPS Monitor.
- Обновлена документация Home Assistant.
- Обновлён `BOT-PASSPORT.md`.
- Удалены устаревшие описания legacy Kuma Healthcheck и Kuma Webhook.
- Документирована новая схема мониторинга VPS.

### Tests

- Добавлены тесты VPS Monitor.
- Добавлены тесты persistent state мониторинга.
- Добавлены тесты независимого monitoring runner.
- Добавлены проверки переходов состояний и подавления повторных уведомлений.
- Добавлены проверки обработки ошибок отправки уведомлений.
- Обновлены тесты deployment и legacy monitoring cleanup.
- Полный набор тестов после изменений проходит успешно. **1472 passed**.

## [1.1.0] - 2026-09-10

### Added

#### Установка

- Добавлена возможность устанавливать Xray отдельно с помощью `-xray`.
- Добавлена возможность устанавливать AmneziaWG отдельно с помощью `-awg`.
- Добавлена возможность устанавливать оба VPN-компонента одновременно.
- Installer теперь устанавливает rclone через официальный install script.
- Добавлены примеры конфигураций Xray и AmneziaWG для первоначальной настройки.

#### Xray

- Добавлена проверка готовности конфигурации VLESS Reality перед созданием клиента.
- Добавлена проверка обязательных параметров Reality-конфигурации.
- Создание Xray-клиента блокируется, если серверная конфигурация не готова.

#### AmneziaWG

- Добавлена проверка готовности серверной конфигурации AmneziaWG перед созданием клиента.
- Проверяется наличие необходимых параметров интерфейса: `PrivateKey`, `Address` и `ListenPort`.
- Создание AWG-клиента блокируется, если серверная конфигурация не готова.

#### Backup

- Добавлено отображение реального прогресса загрузки backup в Telegram.
- В процессе загрузки отображаются процент выполнения, переданный и общий объём данных, скорость и оставшееся время.
- Добавлено сохранение длительности backup в статусе.

### Changed

#### Xray

- Информация о Xray-клиенте в Telegram теперь формируется по фактическим портам и SNI из конфигурации, а не по заранее заданному набору портов.

#### Backup

- Улучшена обработка retention локальных backup: текущий создаваемый архив не удаляется во время очистки.
- Улучшена обработка retention удалённых backup: текущий архив не попадает под удаление.
- Обновлена логика получения статистики загрузки через rclone.
- Улучшена работа ручного backup в Telegram: одно сообщение обновляется по мере выполнения операции и затем заменяется итоговым результатом.
- Добавлена информация о продолжительности backup в итоговое сообщение.

#### Home Assistant

- Список Xray-клиентов в статистике теперь очищается от дубликатов.
- Xray-клиенты в traffic collector группируются по UUID и могут быть связаны с несколькими inbound/портами.

### Fixed

- Исправлено дублирование сообщений при отображении прогресса загрузки backup.
- Исправлено дублирование Xray-клиентов в данных Home Assistant.
- Исправлена обработка текущего backup механизмом retention.

### Documentation

- Существенно обновлена документация по deployment и установке.
- Документированы режимы установки Xray и AmneziaWG.
- Добавлены примеры конфигураций VPN.
- Документированы проверки готовности конфигураций перед созданием клиентов.
- Обновлена документация по backup, rclone и отображению прогресса.
- Обновлена документация по Home Assistant и статистике VPS.

### Tests

- Добавлены тесты проверки готовности Xray-конфигурации.
- Добавлены тесты проверки готовности AmneziaWG-конфигурации.
- Обновлены тесты lifecycle AWG с учётом требований к конфигурации.
- Расширены тесты deployment.
- Добавлены и расширены тесты статистики VPS и Xray traffic collector.
- Обновлены тесты backup retention и ручного backup.
- Полный набор тестов проходит успешно: **1434 passed**.
